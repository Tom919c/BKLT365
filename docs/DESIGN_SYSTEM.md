# 界面与设计系统

版本：v2
最后验证：2026-11-17
适用范围：`niguang365/webui/`

## 1. 设计目标

- **手机优先**：主编在手机上完成同步、选组、组稿、预览、发布、收束与上传处理。
- **照片优先**：组卡片先展示图片/组信息，技术细节退后。
- **状态可见**：入选、已发布、未入选、上传失败、待清理、需重新同步都用文字+色彩双重表达。
- **危险操作说清后果**：取消入选、收束、上传、发布均显示对象和影响。
- **不引入重型框架**：原生 HTML/CSS/JS，FastAPI 直接托管，无构建步骤。

## 3. 视觉语言

| 角色 | 规则 |
|---|---|
| 背景 | 暖白纸感 `#f6f2ea`，细颗粒噪点，避免大面积靛紫渐变 |
| 主色 | 深墨绿/暗红作强调，不使用高饱和霓虹 |
| 字体 | 系统中文无衬线；标题紧凑、正文 1.5 倍行距 |
| 卡片 | 低对比边框 + 轻阴影；照片圆角 |
| 状态 | `collected` 中性、`selected` 暖色、`published` 绿、`unselected` 灰、`failed` 红 |
| 图标 | 尽量用文字/符号，不引入图标字体 |

## 4. 响应式断点

| 宽度 | 布局 |
|---|---|
| < 360 | 单列；按钮可换行；图片网格 2 列 |
| 360—767 | 手机主布局；底部选择栏固定 |
| 768—1439 | 双列组卡片；设置双列 |
| ≥ 1440 | 内容最大宽约束，避免超宽阅读 |

验收重点：无横向溢出；触控目标 ≥ 40px；长文件名/路径可换行；空态/加载/忙碌/错误/持久失败均有明确文案。

## 5. 关键交互

- **按组选择**：组卡片整组选中；底部“已选 N 组/组稿”。
- **合并**：显式勾选多组，标题由主编填写；页码自动连续。
- **预览**：先保存组稿，再生成草稿；未保存不允许预览/草稿。
- **发布**：二次确认 + 勾选“已预览”；结果不确定只提示人工核对。
- **收束/上传**：先展示阻断原因；失败任务持久显示。
- **设置**：业务设置与部署清单分区；系统级变更只展示，不代执行。

## 6. 可访问性

- 表单均有 `<label>`；按钮有明确文本；弹窗有 `aria-modal`/标题。
- 色彩不是唯一状态信号，同时显示文字。
- 错误信息用 `role="alert"`；不把技术堆栈直接抛给主编。
- 键盘：Esc/关闭按钮可关弹窗；焦点进入弹窗标题。
